분석 대상 화면: [개발 서버 URL]
관련 소스: [예: src/pages/order/OrderForm.tsx]

목적: 디자이너가 화면 설계 시 확인해야 할 요소와
      필수값/입력 검증 동작을 스크린샷과 함께 정리한다.

1. 소스 분석 (캡처 전에 결과를 보여주고 내 확인을 받아)
   A. 입력 항목 표
      - 항목명 / 입력 타입(텍스트, 셀렉트, 날짜 등) / 필수 여부
      - 검증 규칙(최대 길이, 형식, 숫자 범위, 항목 간 조건)
      - 에러 메시지 문구 (소스에 있는 그대로)
      - 검증 시점 (입력 중 / 포커스 아웃 / 제출 시)
   B. 버튼 상태 조건
      - 저장·다음 버튼이 비활성화되는 조건
   C. 디자이너 확인 요소
      - 화면 상태: 초기 / 로딩 / 데이터 없음 / 에러 / 권한별 차이
      - 피드백 UI: 토스트, 알림 모달, 확인 다이얼로그와 각 문구
      - 조건부 노출: 특정 값 선택 시 나타나거나 사라지는 영역
      - 기본값, placeholder, 안내 문구
   D. 캡처할 상태 목록

2. 화면 캡처 (확인받은 목록대로)
   - Chrome DevTools MCP를 사용하고, 내가 로그인해 둔 브라우저 창에서 진행해.
     새 브라우저를 띄우거나 스크립트를 작성하지 마.
   - 로그인 화면이 나오면 멈추고 나한테 알려줘.
   - 캡처 대상:
     · 초기 화면
     · 필수값 비운 채 제출 → 에러 표시 상태
     · 형식 오류 입력 시 에러 상태 (항목별 대표 케이스)
     · 조건부 영역이 열린 상태
     · 모달·토스트가 떠 있는 상태
   - 저장: docs/screens/[화면명]/[번호]_[상태명].png
   - 실제 데이터를 저장·삭제·전송하는 동작은 실행 전에 나한테 물어봐.
   - 재현이 어려운 상태는 캡처하지 말고 "소스 기준 설명"으로 표시해.

3. 문서 작성: docs/[화면명].md
   1) 화면 개요 (목적, 진입 경로)
   2) 입력 항목 및 검증 규칙 표
   3) 상태별 스크린샷 + 설명
      (어떤 조작으로 이 상태가 되는지 / 디자이너가 볼 포인트)
   4) 메시지 문구 모음 (에러, 토스트, 모달)
   5) 동작 흐름 (사용자 동작 → 검증 → API → 화면 변화)
   6) 디자인 확인 필요 사항
      (소스상 문구가 하드코딩된 곳, 상태별 UI가 없는 곳 등)
