## Source 탐색 기준

절대경로를 요청하거나 추측하지 마.

Code Index MCP에 현재 설정되어 있는 Project Root를 기준으로
모든 Source를 상대경로로 탐색해.

프로젝트 구분 규칙:

- Backend: `gipms-api-*`
- Frontend: `gipms-*` 중 `gipms-api-*` 제외

Frontend 프로젝트명과 Backend 프로젝트명을
사전에 알고 있다고 가정하지 마.

먼저 대상 API의 Method + URL을 기준으로 관련 Source를 검색해서
실제 관련 프로젝트를 찾아.

탐색 순서:

1. Frontend 후보
   - `gipms-*`
   - 단, `gipms-api-*` 제외
   - 대상 API를 호출하는 Source 검색
   - 실제 호출 Source가 발견된 프로젝트만 이후 분석

2. Backend 후보
   - `gipms-api-*`
   - 대상 API의 Controller Mapping 검색
   - 실제 Mapping이 발견된 프로젝트만 이후 분석

3. 관련 프로젝트가 확인되면
   해당 프로젝트 내부에서만 DTO / Validation / Response를 추적

전체 Frontend/Backend 프로젝트를 순차적으로 읽지 말고
Code Index 검색으로 관련 Source를 먼저 좁혀.

Source Path는 Project Root 기준 상대경로로 출력해.

예:
`gipms-xxx/src/.../EquipmentSearch.tsx`
`gipms-api-xxx/src/.../EquipmentController.java`

Windows 절대경로
`C:\...`
형태의 Source Path는 출력하지 마.

## Evidence 원칙

Code Index MCP는 관련 Source를 찾는 탐색 도구로 사용해.

최종 판단은 반드시 실제 Source 내용을 확인해서 해.

파일명, Class명, Method명 또는 검색 결과만으로
API Contract를 추측하지 마.

Runtime에서 확인된 값은 실제 관찰 사례일 뿐
전체 API Contract로 일반화하지 마.

확인할 수 없는 항목은 추측하지 말고
`확인되지 않음`으로 표시해.

## 분석 경계

다음 영역은 절대 분석하지 마.

- Service
- ServiceImpl
- Mapper
- MyBatis XML
- SQL
- Oracle
- SAP 내부 로직

Controller에서 Service 호출이 발견되더라도
호출 사실까지만 확인하고 내부로 진입하지 마.

Controller / Request DTO / Validation /
Response DTO / Error Response Contract까지 확인한 후 STOP.

문서는 생성하지 말고 테스트 결과만 출력해.
